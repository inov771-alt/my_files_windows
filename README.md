# Мои файлы (MyFiles) — загрузка файлов на files.spkmd.ru

Windows-приложение (Windows 11 x64, C# / .NET 8, Windows Forms) для загрузки файлов
на сервер **https://files.spkmd.ru** прямо из Проводника:

**Выделите файлы → правая кнопка мыши → «Показать дополнительные параметры» → «Отправить» → «Мои файлы».**

Программа умеет работать и самостоятельно: запустите `MyFiles.exe` и нажмите «Добавить файлы».

## Возможности

- Загрузка нескольких файлов; каждый файл отправляется **отдельным запросом** —
  ошибка одного файла не мешает остальным.
- Потоковая загрузка: файл читается с диска порциями по 128 КБ и сразу отправляется
  в сеть. Файлы на 800 МБ и больше **не загружаются в память целиком**.
- Корректная передача кириллических имён файлов (UTF-8, как у браузеров).
- Список файлов с размерами, индикатором прогресса по каждому файлу, общим прогрессом,
  скоростью и статусами: «Ожидание», «Загрузка», «Готово», «Ошибка», «Отменено».
- Понятные тексты сетевых ошибок и ошибок сервера; двойной щелчок по строке с ошибкой — подробности.
- Кнопка «Отмена» (и клавиша Esc). После завершения программа **не закрывается** и показывает итог.
- Повторная загрузка неудачных файлов: нажмите «Загрузить» ещё раз — успешные файлы пропускаются.
- Одно окно: если Проводник передаст очень длинный список файлов несколькими запусками,
  все файлы соберутся в одном окне.
- Перетаскивание файлов мышью в список.
- Поле «Папка на сервере» (поле `dir` API). Пусто — корневая папка.

## API

Используется существующий API без изменений:

- `POST https://files.spkmd.ru/index.php?api=upload`
- `multipart/form-data`: `files[]` — файл, `dir` — каталог назначения (пусто = корень).
- Ответ: `{"ok":true,"uploaded":[...],"failed":[...]}`.

Существующие файлы сервер не перезаписывает. При конфликте имён программа показывает
понятную ошибку: переименуйте файл и загрузите снова.

## Быстрый старт (готовая сборка)

1. Откройте вкладку **Actions** этого репозитория на GitHub.
2. Выберите последний успешный запуск workflow **Build**.
3. Внизу страницы, в разделе **Artifacts**, скачайте `MyFiles-win-x64` (ZIP).
4. Распакуйте архив в **постоянную папку**, например `C:\Tools\MyFiles`
   (не запускайте из папки «Загрузки» или временной папки архиватора: ярлык SendTo
   будет указывать на путь к EXE).
5. Запустите `install_sendto.cmd` — появится пункт «Отправить → Мои файлы».
   Права администратора не нужны.
6. Выделите файлы в Проводнике → правая кнопка → «Показать дополнительные параметры» →
   «Отправить» → «Мои файлы». Загрузка начнётся автоматически.

EXE самодостаточный (self-contained, single-file): **.NET на компьютере пользователя не нужен**,
установка программы не требуется — просто папка с файлом.

> Windows SmartScreen может предупредить о неизвестном издателе (файл не подписан цифровой
> подписью). Нажмите «Подробнее» → «Выполнить в любом случае».

## Удаление пункта из Проводника

Запустите `uninstall_sendto.cmd` из той же папки. Ярлык «Мои файлы» будет удалён из SendTo.
Сам `MyFiles.exe` при желании удалите вместе с папкой вручную.

## Сборка через GitHub Actions

Workflow `.github/workflows/build.yml` запускается автоматически при каждом push в ветку
`main` и вручную (вкладка Actions → Build → «Run workflow»). Он выполняет публикацию:

```
dotnet publish MyFiles.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish
```

и выкладывает Artifact `MyFiles-win-x64`, внутри которого:

- `MyFiles.exe` — готовая программа (примерно 70–90 МБ, это нормально для self-contained);
- `install_sendto.cmd` / `install_sendto.ps1` — установка пункта «Отправить → Мои файлы»;
- `uninstall_sendto.cmd` / `uninstall_sendto.ps1` — удаление пункта;
- `README.md` — эта инструкция.

## Локальная сборка (необязательно)

Нужен только .NET 8 SDK (Visual Studio не требуется): запустите `publish_local.cmd`
или выполните команду публикации из раздела выше. Результат — `publish\MyFiles.exe`.

## Ограничения (честно)

- Программа не обходит серверные лимиты PHP (`upload_max_filesize`, `post_max_size`,
  `max_execution_time` и т.п.). Если сервер настроен, например, на 100 МБ, файл на 800 МБ
  будет отвергнут сервером (программа покажет понятную ошибку, например HTTP 413).
  Клиентская часть потоковая и ограничений на размер не имеет.
- Серверная часть не менялась и не должна меняться: программа использует только
  существующий API.
- EXE не подписан цифровой подписью (см. примечание про SmartScreen выше).

## Структура репозитория

```
MyFiles.csproj                  — проект .NET 8 (WinForms)
app.manifest                    — DPI, длинные пути, права asInvoker
Program.cs                      — точка входа, одно окно приложения
MainForm.cs                     — интерфейс и логика очереди загрузки
SingleInstance.cs               — передача файлов повторных запусков в первое окно
Utils.cs                        — форматирование размеров/скорости
Upload/UploadItem.cs            — модель файла в очереди
Upload/UploadClient.cs          — HTTP-клиент, по одному POST на файл
Upload/StreamingMultipartContent.cs — потоковое multipart-тело с прогрессом
Upload/ServerResponse.cs        — разбор ответа сервера и ошибок
Upload/UploadResult.cs          — результат загрузки файла
scripts/                        — установка/удаление пункта SendTo
publish_local.cmd               — локальная сборка одним запуском
.github/workflows/build.yml     — сборка EXE в GitHub Actions + Artifact
```
